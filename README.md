# 日切放行

> 遵守 `ops/底座生成前必读_效率与技术栈.md`。FastAPI + Vue 3 + SQLite，交付须 docker compose 一键起；库用 SQLite，不挂外置 Postgres。  
> **禁止同构换皮**：本仓主链路、表结构、接口与页面均独立，不得与其它仓共用同一套 `/api/items` 壳。

## 骨架一句话

业务日分区切片登记后裁决完整度，完整才放行下游，并与消费水位对账

## 为何能出多题

迟到切片、重切、跨分区依赖、部分完整冻结、消费水位回拨

## 避开

别做成作业拓扑编排换皮；别做成纯水位大盘

## 互斥切口候选

- 迟到切片整批拒收 vs 进待补齐冻结区
- 重切失败整笔回滚 vs 保留已完整分区
- 放行与水位同步闸 vs 异步放行后纠偏
- 跨分区依赖闸：任一分区未完整整组禁止 vs 分区独立登记、组齐后水位一次推进

## 依赖闸（本仓已落地）

同一业务日声明互为依赖的分区，一律按依赖闸裁决，不再允许单分区偷放行、半员放行推水位。

**口径只钉死一种：乙写法**（写入 `dependency_policies`，当天不得更换）：

> 各分区独立登记完整度、独立放行；消费水位只在组内全员完整且全部成功放行后**一次**推进。

甲写法（组内任一分区未完整则整组禁止放行且禁止推水位）为互斥备选，本库不实现、不接受切换；
请求携带异口径即拒绝并记 **依赖口径偏了**。

规则要点：

| 场景 | 裁决 |
|------|------|
| 依赖组成员未完整 | 拒绝放行，水位不推进 |
| 组成员完整但组未齐 | 允许该分区独立放行，水位**不**推进 |
| 全员完整且全部成功放行 | 水位一次推进，来源切片为全组成员拼接 |
| 绕过依赖声明按旧切片/重复放行 | 拒绝并审计 |
| 同一依赖组两人同时放行 | 排队互斥，后到记 **依赖争用**，拒绝默成 |
| 请求携带异口径 / 当天换口径 | 拒绝并记 **依赖口径偏了** |

同源可核：依赖目录、分区详情、水位页、切片列表旁注全部由同一套依赖闸计算派生，
历史（闸前）单分区水位保留为审计记录并标记越界，按口径补齐后标记为“已纠正”。

接口：

- `GET /api/dependencies` 依赖目录
- `GET /api/dependencies/register` 依赖闸口册（口径 + 流水）
- `GET /api/partitions/{biz_date}/{partition_key}` 分区详情
- `POST /api/dependencies/policy` 钉口径（当天不可改）
- `POST /api/dependencies/groups` 声明依赖组
- `POST /api/slices/{id}/release` 放行（组成员自动走依赖闸）
